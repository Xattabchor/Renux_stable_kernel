# PhantomMask — Symbian GLES 1.1 / VGP port

This project packages the actual PhantomMask scene, not a geometry smoke test. The app renders the animated mask mesh from the PowerVR POD scene, draws the original room panorama behind it, applies the original nine-term SH coefficients through the compiled IMG VGP program, and runs the 451-frame scene animation at 30 fps. It requests an OpenGL ES 1.1 context and targets the ARMv5T E32 profile for Symbian OS 9.x loader compatibility on N95-class phones.

`phantom_mask_scene_data.h` contains the mask mesh (2238 vertices, 4480 triangles), camera data, and per-frame model transforms generated from the SDK PhantomMask POD scene. `assets/MaskMain.pvr` and `assets/RoomStill.pvr` are the original PVR v2 texture files. Both were checked against the original files embedded in the OGLES1.1 SDK executable: `flags & 0xff == 0x19` (`OGL_PVRTC4`, PVRTC1 4 bpp), with their original mip chains and SHA-256 values. The build runs `verify_assets.py`; texture data is embedded unchanged and is not transcoded to PVRTC2.

The vertex shader is loaded from the repository's already-compiled `SGX/VGP/build/PhantomMask_SH.bin`, copied unchanged to `assets/PhantomMask_SH.bin` and embedded in the executable. Its `VGP ` signature, 1412-byte size, and SHA-256 are verified before compiling. At startup the app checks `GL_IMG_vertex_program` and the required entry points. If VGP is unavailable or its program setup fails, a persistent on-screen status is shown (including `VERTEX PROGRAM / NOT SUPPORTED` when appropriate); press any key to continue with fixed-function lighting. This fallback does not perform spherical-harmonics lighting.

The app dynamically loads the legacy `libgles_cm.dll` EGL/GLES 1.1 exports, matching the compatibility path used by the Symbian Quake III port; it does not import the newer separate `libegl.dll` or `libglesv1_cm.dll` proxies. Its EGL 1.1 configuration matches `EGL_BUFFER_SIZE` to the native `RWindow::DisplayMode()` (12/16/24/32 bits) and requests a 16-bit depth buffer, following the Symbian guidance and Quake III path. The SIS is built with `symbian-platform` 0.3.0 using the SDK archive obtained from Google Drive. The archive SHA-256 is verified against the release asset before the build. The output is unsigned and marked as an experimental E32 executable by the SDK; successful packaging does not establish Symbian loader acceptance or runtime compatibility. Physical-device VGP rendering still needs testing.
